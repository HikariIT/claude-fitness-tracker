# 2. Install dependencies and set up Vitest
**Decisions:** D1, D3, D4
**Notes:** Config is `vitest.config.mts`, not `.ts`: Node 22.11 cannot `require()` the ESM-only `std-env` that Vitest loads from a `.ts` config.

Goal: add the packages from step 2 of `CLAUDE_ARCHITECTURE.md` with exact versions, plus a minimal Vitest setup. Use npm only: it is the sole package manager, and `package-lock.json` must be updated.

Steps:
1. Runtime deps (D1, D4):
   `npm install --save-exact drizzle-orm pg zod drizzle-zod server-only`
2. Dev deps (D1, D4):
   `npm install --save-exact --save-dev drizzle-kit @types/pg vitest`
3. If npm reports a peer-dependency conflict (e.g. drizzle-zod vs zod major version), pick the newest versions that satisfy each other's peers. Do not use `--force` or `--legacy-peer-deps`. Note the chosen versions in the Change Log.
4. Create `vitest.config.ts` at the project root (D3):
   ```ts
   import { fileURLToPath } from "node:url";
   import { defineConfig } from "vitest/config";

   export default defineConfig({
     resolve: {
       alias: { "@": fileURLToPath(new URL("./src", import.meta.url)) },
     },
     test: {
       environment: "node",
       include: ["src/**/*.test.ts"],
     },
   });
   ```
   The alias mirrors `tsconfig.json` `"@/*": ["./src/*"]` (set in subtask 1).
5. In `package.json` `scripts`, add `"test": "vitest run --passWithNoTests"` after `lint`. No tests exist yet, and the flag keeps the command green. Do NOT add the `db:*` scripts or `drizzle.config.ts` (D3).
6. Do not touch `Dockerfile` or the compose files. `npm ci` there picks up the new lockfile.

**Files:**
- Create: `vitest.config.ts`
- Modify: `package.json`: new deps, devDeps and the `test` script
- Modify: `package-lock.json`: regenerated by npm

**Read:** `package.json`, `tsconfig.json`, `CLAUDE_ARCHITECTURE.md` (section "Setup steps", at the end of the file)

**Verify:** `npm test; if ($?) { npx tsc --noEmit }; if ($?) { npm run lint }`
