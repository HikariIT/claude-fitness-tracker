# 2. Drizzle client, db:check script and src/db/AGENTS.md
**Decisions:** D1, D3, D4, D5, D6

Goal: a server-only Drizzle client and `npm run db:check`, which runs `SELECT 1` against the database from subtask 1 and exits 0 on success, 1 on failure. No schema, tables, migrations or `drizzle.config.ts` (D5).

Installed versions (already in `package.json`): `drizzle-orm` 0.45.4, `pg` 8.23.1, `@types/pg` 8.23.1, `server-only` 0.0.1. Host Node is 22.11 (supports `--env-file-if-exists`). `tsconfig.json` maps `@/*` to `./src/*`.

Steps:
1. Install tsx (D4), exact version, npm only (no `--force`/`--legacy-peer-deps`):
   `npm install --save-exact --save-dev tsx`
2. Create `src/db/client.ts` (D1):
   ```ts
   import "server-only";
   import { drizzle } from "drizzle-orm/node-postgres";
   import { Pool } from "pg";

   const connectionString = process.env.DATABASE_URL;
   if (!connectionString) {
     throw new Error("DATABASE_URL is not set. Copy .env.example to .env.local.");
   }

   // Reuse one pool across Next.js dev hot reloads.
   const globalForDb = globalThis as unknown as { pgPool?: Pool };
   export const pool = globalForDb.pgPool ?? new Pool({ connectionString });
   if (process.env.NODE_ENV !== "production") globalForDb.pgPool = pool;

   export const db = drizzle({ client: pool });
   ```
   No `schema` option yet (no schemas exist).
3. Create `src/db/check.ts` (D1). It is a CLI script, not imported by the app:
   ```ts
   import { sql } from "drizzle-orm";
   import { db, pool } from "@/db/client";

   async function main() {
     try {
       const result = await db.execute<{ ok: number }>(sql`select 1 as ok`);
       console.log(`Database connection OK (select 1 -> ${result.rows[0]?.ok})`);
       process.exitCode = 0;
     } catch (error) {
       console.error("Database connection FAILED:", error);
       process.exitCode = 1;
     } finally {
       await pool.end();
     }
   }

   void main();
   ```
   Console text here is CLI output, not UI, so the language-map rule does not apply.
4. In `package.json` `scripts`, add after `test` (D4):
   `"db:check": "tsx --conditions=react-server --env-file-if-exists=.env.local src/db/check.ts"`
   - `--conditions=react-server` makes `server-only` resolve to its empty module instead of throwing.
   - Env vars already set in the process (e.g. `DATABASE_URL` from compose) win over `.env.local`.
   Do NOT add `db:generate`, `db:migrate`, `db:seed` or `drizzle.config.ts` (D5).
5. If `tsx` does not resolve the `@/` alias, switch the import in `check.ts` to `./client` and note it in the Change Log.
6. Update `CLAUDE_ARCHITECTURE.md` only in the "Setup steps" list: append ` (done: FIT-6, plus npm run db:check)` to step 3. Nothing else.
7. Create `src/db/AGENTS.md` (D6), a short navigator for agents working in `src/db/` (at most ~40 lines, plain Markdown). Describe only what exists after this task and mark the rest as planned:
   - **Purpose:** the database layer (PostgreSQL 17 + Drizzle ORM). Only `src/db/` and `src/server/` may touch the database. Never import `src/db/` from `src/app/`, `src/components/` or client code.
   - **Files:** `client.ts` (server-only pg `Pool` + Drizzle `db` singleton, reads `DATABASE_URL`, pool cached on `globalThis` in dev) and `check.ts` (CLI `SELECT 1` check, not imported by the app).
   - **Connection:** credentials `postgres`/`postgres`, database `fitness_tracker` (see `.env.example`). Host scripts use `localhost:5432` from `.env.local`; inside compose the host is `db` (the dev `web` service overrides `DATABASE_URL`). Port 5432 is published only in `docker-compose.dev.yml`.
   - **Commands:** `docker compose -f docker-compose.dev.yml up -d --wait db` to start Postgres, then `npm run db:check`. Explain why the script uses `tsx --conditions=react-server` (so `import "server-only"` does not throw outside Next).

Point to `CLAUDE_ARCHITECTURE.md` ("Data model") for details.
