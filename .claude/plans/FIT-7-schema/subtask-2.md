# 2. Migration tooling, first migration, dev compose
**Decisions:** D7, D9

Goal: add drizzle-kit config and the `db:generate` / `db:migrate` scripts, generate the first migration from the schema in `src/db/schema/` (built in subtask 1), apply it to the dev database, and make dev compose migrate before `next dev`.

Installed: `drizzle-kit` 0.31.11, `drizzle-orm` 0.45.4, `tsx` 4.23.15. The existing `db:check` script is:
`"db:check": "tsx --conditions=react-server --env-file-if-exists=.env.local src/db/check.ts"`
(`--conditions=react-server` makes `import "server-only"` resolve outside Next.js.)

Steps:
1. Create `drizzle.config.ts` in the repo root:
   ```ts
   import { defineConfig } from "drizzle-kit";

   export default defineConfig({
     dialect: "postgresql",
     schema: "./src/db/schema/index.ts",
     out: "./src/db/migrations",
     casing: "snake_case",
     dbCredentials: { url: process.env.DATABASE_URL ?? "" },
     strict: true,
     verbose: true,
   });
   ```
   `casing: "snake_case"` must match the `casing` passed to `drizzle()` in `src/db/client.ts`.
2. Create `src/db/migrate.ts` (CLI only, not imported by the app). Same shape as `src/db/check.ts`:
   ```ts
   import { migrate } from "drizzle-orm/node-postgres/migrator";
   import { db, pool } from "@/db/client";

   async function main() {
     try {
       await migrate(db, { migrationsFolder: "src/db/migrations" });
       console.log("Migrations applied");
       process.exitCode = 0;
     } catch (error) {
       console.error("Migration FAILED:", error);
       process.exitCode = 1;
     } finally {
       await pool.end();
     }
   }

   void main();
   ```
   Console text is CLI output, so the language-map rule does not apply.
3. In `package.json` `scripts`, add after `db:check`:
   - `"db:generate": "drizzle-kit generate"`
   - `"db:migrate": "tsx --conditions=react-server --env-file-if-exists=.env.local src/db/migrate.ts"`
4. Run `npm run db:generate`. It must create `src/db/migrations/0000_*.sql` plus `meta/`. Open the SQL and check: tables `settings`, `foods`, `diary_entries`, `workouts`, `treadmill_sessions`, `exercises`, `workout_sets`; enums `sex`, `activity_level`, `meal`, `workout_type`; snake_case columns (`protein_g`, `food_id`, `created_at`); `GENERATED ALWAYS AS IDENTITY` (D7). If the columns come out camelCase, `casing` is missing in the config: fix it and regenerate (delete the bad migration folder first). Do not hand-edit the SQL. Commit the folder (it is not git-ignored).
5. In `docker-compose.dev.yml`, change the `web` service `command` to:
   `sh -c "npm install && npm run db:migrate && npm run dev"`
   Inside compose, `DATABASE_URL` is already overridden to host `db`. Do NOT change `docker-compose.yml` (prod comes later, D9).
6. Start the DB and apply: `docker compose -f docker-compose.dev.yml up -d --wait db`, then `npm run db:migrate`. Running it twice must be a no-op.
